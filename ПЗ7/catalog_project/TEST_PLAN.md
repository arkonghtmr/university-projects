# Test Plan Identifier

TP-AKB-2026-06

# Introduction

Тест-план описывает проверку шестой практической работы "Проект каталог. Работа с данными" для магазина аккумуляторов. Проверяется разграничение ролей, изменение каталога через интерфейс, формирование партии товара на отправку и расчет суммы партии с оптовыми ценами и дополнительной скидкой.

# Test Items

Проверяемые модули:

- `catalog.models`: `Battery`, `Shipment`, `ShipmentItem`;
- `catalog.forms`: `BatteryForm`, `ShipmentForm`, `ShipmentItemForm`;
- `catalog.views`: каталог, формы товара, партии на отправку;
- `catalog.urls`: маршруты каталога, CRUD товара и партий.

# Features to be tested

- гость может просматривать каталог, карточку товара и About;
- гость не может создавать/редактировать/удалять товар и работать с партиями;
- товаровед может создавать, редактировать и удалять товары;
- менеджер продаж может создавать партии на отправку и добавлять товары в свои партии;
- менеджер продаж не может менять партию другого менеджера;
- администратор может работать с товарами и открывать партии менеджеров;
- в товаре есть цена за единицу, цена мелкого опта, цена крупного опта и пороги количества;
- форма товара валидирует оптовые цены и пороги;
- партия считает сумму по правильному уровню цены;
- партия применяет дополнительную скидку к общей сумме;
- URL строятся через `reverse()` и ведут к нужным view;
- корректно изменяются объекты каталога и партии после POST-запросов.

# Features NOT to be tested

- Selenium/E2E-сценарии в браузере;
- внешний API;
- оплата и доставка;
- восстановление пароля;
- права доступа внутри Django admin;
- конкурентное редактирование одной партии в реальном времени.

# Approach

Тестирование выполняется через `django.test.TestCase` и `django.test.Client`. Пользователи и роли создаются в `setUpTestData` через Django `Group`. Для ролей используются группы `Товароведы` и `Менеджеры продаж`, администратор проверяется через `is_superuser`. POST-запросы проверяют реальные изменения объектов в тестовой базе.

# Item Pass/Fail Criteria

Тест считается пройденным, если пользователь с нужной ролью получает доступ к разрешенной операции, пользователь без роли получает отказ или redirect на вход, данные после POST-запроса изменяются корректно, а итог партии совпадает с расчетом по оптовым ценам и дополнительной скидке.

# Suspension Criteria

Тестирование приостанавливается, если не применяются миграции, не создается тестовая база, падает более 30% тестов, или невозможно создать пользователей с ролями.

# Test Deliverables

- исходный код моделей, форм, views, urls и шаблонов;
- пакет тестов `catalog/tests`;
- скриншоты страниц в `ПЗ6/screenshots`;
- отчет `ПЗ6/ОТЧЕТ.md`;
- вывод `python manage.py test catalog.tests --verbosity=2`;
- вывод `coverage run --source='.' manage.py test catalog.tests` и `coverage report`.
